# Auditoria de operações administrativas

## Escopo e critério

Inventário fechado em 13/07/2026 na branch `codex/reconstrucao-astro`. Foram auditadas as 33 rotas do menu administrativo, rotas de criação/edição/histórico e 61 caminhos de API administrativa. Nenhum item ficou classificado como “não testado”.

Critérios usados:

- **E2E rota:** login real, resposta 200, `<main>` visível, sem 404/500/503, erro de console ou navegação para `/api/`.
- **E2E CRUD:** mutação real em PostgreSQL no build de produção, validação pública e limpeza/arquivamento.
- **Contrato:** testes automatizados de inventário, método, autenticação central, origem confiável, envelope JSON e ausência de link/formulário direto para API.
- **Unitário:** validação de schema, arquivo, storage, seeds, API response ou regra de domínio.

Todos os endpoints `/api/admin/**` passam pelo middleware de autenticação, CSRF/origem, `requestId`, normalização de resposta e log estruturado. As permissões específicas continuam sendo verificadas na rota. Downloads CSV preservam resposta binária.

## Correções transversais confirmadas

- Nenhuma ocorrência de `href="/api/`, `action="/api/`, `formaction="/api/` ou redirect de página para API nas rotas administrativas.
- Nenhum uso proibido de `z.email()` ou `z.uuid()` nas APIs e schemas compartilhados.
- Formulários administrativos usam o bridge comum, preservam o submitter, exibem mensagem clara e `requestId`, e tratam downloads separadamente.
- Respostas JSON antigas mantêm campos de compatibilidade no topo, além do envelope canônico `data`, para evitar quebra de consumidores já publicados.
- O E2E produtivo percorreu as 33 rotas do menu e os fluxos mutáveis críticos. O teste estático de inventário falha se uma nova rota/API escapar das regras centrais.
